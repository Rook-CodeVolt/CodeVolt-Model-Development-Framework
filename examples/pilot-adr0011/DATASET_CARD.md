# Dataset card: ADR-0011 MiniMind pilot unit-conversion task (`adr0011-pilot-train-v1` / `adr0011-pilot-heldout-v1`)

Per `docs/DATA_GOVERNANCE.md`'s requirement that every dataset have a
versioned card identifying origin, ownership/licence, collection method,
intended use, prohibited use, transformations, filters, known
limitations, privacy review, and content hash.

- **Dataset id / version**: `adr0011-pilot-train-v1` (train split),
  `adr0011-pilot-heldout-v1` (held-out split) — the exact package ids
  `docs/decisions/0011-minimind-bounded-pilot-plan.md`'s "Dataset"
  section proposes.
- **Location**: `examples/pilot-adr0011/train.jsonl` (train),
  `examples/pilot-adr0011/held_out.json` (held-out).
- **Generator**: `examples/pilot-adr0011/generate_dataset.py` —
  deterministic, fixed seed `20260918`, stdlib-only.
- **Size**: 40 train records, 10 held-out examples (mirrors
  ADR-0006/`examples/pilot-adr0006`'s own 40/10 split size, a
  deliberately small, bounded pilot dataset, not a claim of broad
  coverage).

## Origin / collection method

100% synthetic, deterministically generated by `generate_dataset.py`
for this specific purpose (ADR-0011's MiniMind pilot). No example was
scraped, copied, adapted, or derived from any third-party corpus,
benchmark, or dataset, and none was reused from any other package
already registered in this repository: not ADR-0006's arithmetic pairs
(`examples/pilot-adr0006/`), not ADR-0008's safety probes
(`examples/safety-probes-wpb/`), and not any `evaluator_contract.py`
test fixture. The generator's own disjointness check (`overlap == 0`
between train and held-out *content* triples of
`(unit_from, unit_to, value)`, not merely ids) is run and printed at
generation time, and is independently re-verified by this dataset's
registration test (`tests/test_pilot_adr0011_dataset.py`).

## Task / format

Single-turn SI-prefix unit-conversion task (e.g. "Convert 7 kilometres
to metres." -> "7 kilometres = 7000 metres."), covering a small,
enumerable set of conversions (km<->m, kg<->g, l<->ml, m<->cm, m<->mm,
g<->mg, cl<->ml, km<->cm) with exact-integer answers (no rounding
ambiguity). All conversion factors and value ranges are chosen so
`value * factor` is always an exact integer.

- **Train format**: MiniMind's `SFTDataset` chat-JSONL schema
  (`dataset/lm_dataset.py`) — one JSON object per line, shaped as
  `{"conversations": [{"role": "user", "content": ...}, {"role":
  "assistant", "content": ...}]}`. This is MiniMind's own multi-turn
  chat schema (used here single-turn), deliberately distinct from
  TRL's flat prompt/completion `{"text": ...}` records ADR-0006's
  pilot dataset used — a new, previously unexercised shape through
  this repository's data-governance tooling, per ADR-0011's explicit
  requirement.
- **Held-out format**: `evaluator_contract.HeldOutExample`-shaped JSON
  (`example_id`, `input`, `expected`), scored via `TaskType.EXACT_MATCH`
  (the default task type) — the prompt asks for a conversion, and
  `expected` is the bare converted integer value as a string.

## Ownership / licence

Original work, contributed under this repository's Apache-2.0 licence
(see `LICENSE`), same as the rest of the repository's source and
examples. No third-party copyrighted or licensed material is embedded.
`dataset_licence="synthetic-CodeVolt-owned"` (the same value ADR-0006's
pilot dataset used), satisfying `TrainingInputs.validate()`'s
non-empty-`dataset_licence` requirement.

## Intended use

Exercises the ADR-0011 MiniMind pilot's data-governance and
contamination-check preconditions specifically — a fixed, versioned,
disjoint train/held-out split registered via
`HeldOutExclusionRegistry`, so `evaluator_contract.run_evaluator_contract`'s
bidirectional `check_held_out_not_trained` precondition has real content
on both sides to check against (per ADR-0011's "Independent evaluation
wiring" section). It is intended, if and when the pilot is separately
authorised, to be the dataset an eventual `MiniMindTrainerAdapter.train()`
call and a real evaluator adapter (e.g.
`HFLocalCausalLMEvaluatorAdapter`) would train against and score
against respectively. Building this artifact does **not** itself
authorise, schedule, or execute any training run.

## Prohibited use

- Held-out split (`held_out.json`) must never be used as training
  data by any package — doing so would contaminate it, and is exactly
  what `HeldOutExclusionRegistry.check_held_out_not_trained` /
  `register_package_train` / `register_package_held_out` exist to
  catch and refuse. No exemption for this package.
- Train split (`train.jsonl`) must never be scored as, or substituted
  for, a held-out set for any package — the reverse direction of the
  same contamination class (issue #11).
- Not to be presented as a general-purpose unit-conversion benchmark —
  it is a narrow, deliberately small (40/10), fixed-format pilot
  dataset built for one specific bounded pilot's precondition, not a
  claim of broad task coverage.
- Not to be used to derive an automated accept/reject/promotion gate
  without a separate, explicit governance decision (`docs/ARCHITECTURE.md`
  core contract #6; `docs/EVALUATION_POLICY.md`).
- Building or registering this dataset does not authorise, and must
  not be treated as authorising, any live MiniMind training run or the
  evaluator adapter's real inference — that remains gated per
  ADR-0011's "Gating" section (the pilot-specific live-execution
  security review, then separate owner authorisation).

## Transformations / filters

None beyond the generator's own direct construction. `generate_dataset.py`
samples `(unit_from, unit_to, value)` triples from a fixed enumerable
conversion table via `random.Random(20260918)`, renders each triple
directly into its final JSONL/JSON shape, and excludes any triple
already assigned to the other split before sampling it — no external
filtering pipeline, no post-processing, no data collected then filtered
down.

## Known limitations

- 40 train / 10 held-out is a small, deliberately bounded pilot
  dataset (mirroring ADR-0006's own 40/10 split size), not a
  comprehensive unit-conversion benchmark. It covers 8 specific
  SI-prefix conversion pairs only.
- English-only, single-turn only, and restricted to integer input
  values within each conversion's chosen range — no fractional values,
  no multi-step conversions (e.g. km -> cm via m), no unit families
  beyond length/mass/volume.
- Exact-match scoring (`TaskType.EXACT_MATCH`, the default) requires
  the evaluator's output to contain the bare expected integer string;
  a model producing a numerically-correct but differently-formatted
  answer (e.g. with a decimal point, or in scientific notation) would
  be scored incorrect under this held-out set's current `expected`
  values — a known scoring-mode limitation, not a claim that this
  dataset measures general conversion "understanding."

## Privacy review

No personal, customer, confidential, or restricted data of any kind is
present or referenced — every record is a purely synthetic arithmetic
conversion statement over small integers and fixed unit names. No
privacy review escalation was required under `docs/DATA_GOVERNANCE.md`'s
"quarantine uncertain data until a human completes licence and privacy
review" rule, because no uncertain/real personal data exists in either
file to begin with.

## Contamination check

Both splits are registered in a fresh `HeldOutExclusionRegistry`
(`examples/pilot-adr0011/held_out_exclusion_registry.json`): train ids
`adr0011-train-0001..adr0011-train-0040` under package id
`adr0011-pilot-train-v1`, held-out ids
`adr0011-heldout-0001..adr0011-heldout-0010` under package id
`adr0011-pilot-heldout-v1`. Disjointness is enforced at generation time
on the *content* triple `(unit_from, unit_to, value)`, not merely on
generated ids (`generate_dataset.py`'s own `overlap == 0` check), and
independently re-verified by `tests/test_pilot_adr0011_dataset.py`,
which asserts:

1. `HeldOutSet.create("adr0011-pilot-heldout-v1", ...).validate()`
   passes (no tamper, no duplicate ids).
2. `registry.register_package_train(...)` and
   `registry.register_package_held_out(...)` both succeed without
   raising `ContaminationError` when registered in either order.
3. `registry.check_held_out_not_trained(held_out_set.example_ids)`
   returns an empty `frozenset` — the exact precondition
   `evaluator_contract.run_evaluator_contract` re-checks at evaluation
   time (issue #11's bidirectional check), confirmed to pass here
   statically, with **no real training and no real evaluator
   inference executed by that test**.

## Content hash

This file's content hash is whatever `HeldOutSet.create(...)` computes
over the held-out split at load time (the same deterministic,
order-independent hash mechanism every other held-out set in this
repository uses); no separate hash is pinned in this card because the
file itself, under version control, is the immutable source of truth
for this version. Any future change to these examples must land as a
new dataset version (e.g. `adr0011-pilot-heldout-v2`), per
`docs/DATA_GOVERNANCE.md`'s "Dataset changes create a new immutable
version" rule.
