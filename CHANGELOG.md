# Changelog

## [Unreleased]

### Added

- Initial experiment, evidence, decision, and learning contracts.
- Deterministic reference adapters and CLI.
- Governance, contribution, security, support, and architectural documentation.
- Repository-level agent instructions and a structured agent-feedback route.
- Evaluation, data-governance, experiment, dataset, model-card, and release-readiness templates.
- Governed research-source admission, dataset-version contracts, and continual-improvement lifecycle.
- Agent resumption, backlog reconciliation, and experimental-repository migration work packages.
- TrainerAdapterV1 real-engine implementation for TRL (`TRLTrainerAdapter`), gated by ADR-0005; contract conformance tests reused wherever provable without a real training run. No real pilot run performed or authorised by this change.
- `TRLTrainerAdapter`'s TRL version bound pinned from a range to the exact verified version (`trl==0.24.0`), per ADR-0005's amendment addressing a medium finding in Maya's PR #15 review.
- `EvaluatorAdapterContract` v1 (`src/codevolt_mdf/evaluator_contract.py`), a separate, contract-tested independent-evaluation harness for issue #7 step 4, plus a deterministic `FakeEvaluatorAdapter` for its conformance tests. Not wired into `TRLTrainerAdapter` or `trainer_contract.py` (verified by a structural test).
- `HeldOutExclusionRegistry` (`src/codevolt_mdf/held_out_registry.py`), a bidirectional, per-package held-out/train exclusion registry reusing the design pattern from issue #11/`docs/DATA_GOVERNANCE.md`; used by the evaluator contract to reject a held-out set contaminated by any package's prior train usage before scoring.
- ADR-0006 (`docs/decisions/0006-bounded-real-trl-pilot-plan.md`): drafts the bounded real TRL pilot's exact configuration (model, dataset, concurrency, resource limits, gating). Does not authorise pilot execution.
- ADR-0013 (`docs/decisions/0013-bounded-pretrained-metatrainer-cycle.md`) and its gated runner/plan: propose one pretrained SmolLM2-135M-Instruct full-SFT meta-trainer cycle with immutable hashes, baseline-before-training, identical post-evaluation, semantic rubric, retention gates, resource ceilings, and exact-SHA review evidence. Validation-only mode is exercised; no training is performed or authorized by this change.
- ADR-0013 Gate 1 remediation: adds macOS Seatbelt enforcement for the complete live runner and descendants, exact reviewed host paths, a second mandatory security scope token, and role-specific signer-principal governance. The exact Python 3.9.6 environment passes validation-only with `training_called=false`; live execution remains blocked until holder-supplied public keys and independent approvals are admitted.
- ADR-0013's live cycle ran to completion (`adr0013-metatrainer-sft-20260920`, commit `13b316e`): the pipeline, security gates, and evaluation all worked correctly, and produced an honest negative result — candidate scored worse than baseline on all three suites (meta_trainer 0.0%->0.0%, capability_retention 30.0%->0.0%, safety 46.7%->33.3%), matching ADR-0013's own predeclared "stop and reject" trigger. Raw outputs show classic full-parameter-SFT overfitting/degeneration on the 40-example corpus. No promotion, retry, or in-place parameter change performed under ADR-0013.
- ADR-0014 (`docs/decisions/0014-corrected-bounded-metatrainer-cycle.md`) and its gated runner `examples/pilot-metatrainer-v2/run_bounded_cycle_adr0014.py`: propose a corrected bounded pretrained meta-trainer cycle, citing ADR-0013's rejection above as the evidence basis. Reuses ADR-0013's model identity, corpus, evaluator, contamination machinery, and resource budget unchanged; changes only `max_steps` (120->40, one epoch instead of three) and `learning_rate` (1e-5->5e-6, halved), with documented rationale, under a fresh run id (`adr0014-metatrainer-sft-20260922`) and approval namespace (`codevolt-adr0014`). Validation-only mode is exercised (`status: PASS`, `training_called: false`, all dataset/renderer/held-out hashes verified identical to ADR-0013's); no training is performed or authorized by this change.
- ADR-0014's live cycle ran to completion (`adr0014-metatrainer-sft-20260922`, commit `48db059`): pipeline mechanics sound, capability retention improved over ADR-0013 (safety 46.7%->46.7% preserved, arithmetic 30%->20% mostly preserved), but the `meta_trainer` target-task rubric threshold was missed (0.45/4.0 against the required >=3.0/4.0) and the target-task exact-match score remained 0.0%, matching all three real runs to date. Root-cause diagnosis found the untrained baseline also scores exactly 0.0% on this suite, establishing the exact-match string-containment scorer has no dynamic range for this free-form, sentence-length-answer task; corpus size was identified as a separate, currently unfalsifiable compounding factor. The same run captured a real, safety-relevant confabulation: a fabricated, uncited numeric learning-rate recipe on held-out item `mtr-v2-heldout-0013`.
- ADR-0015 (`docs/decisions/0015-metatrainer-corpus-v3.md`) proposes `examples/pilot-metatrainer-v3/`, a new, standalone 160-record (112 train / 48 held-out) meta-trainer corpus for repository admission: merges corpus v2 (60 records, unchanged) and the independently-audited training-history addition (12 records, one audit-recommended fix applied) with 88 new records emphasizing calibrated uncertainty and refusal, directly motivated by the real confabulation finding above. Does not touch, replace, or invalidate `pilot-metatrainer-v2/`'s files/hashes or ADR-0013/ADR-0014's already-recorded results, and does not itself authorize any training run. Self-audit report and two explicitly flagged not-yet-independently-confirmed citation sub-claims are recorded in `examples/pilot-metatrainer-v3/SELF_AUDIT_REPORT.md`.
- ADR-0015's real gated execution ran to completion at commit `e19dee1` (`adr0015-metatrainer-sft-20260922`): training accepted under the corrected 16,384MB memory ceiling (real peak 12,119.7MB). The automated `exact_match` scorer read `meta_trainer` 0.0%->0.0% (unchanged from both the untrained baseline and ADR-0013/ADR-0014's own candidates), while capability_retention (30.0%->20.0%) and safety (46.7%->40.0%) both regressed slightly relative to ADR-0014's fully/partially-preserved result. An independent manual rubric review of the same ADR-0015 candidate, incorporated into `docs/decisions/ADR-0015-outcome.md` after Maya's round-1 review of PR #91 caught its omission from the initial draft, found a strictly monotonic 4-run rubric-mean trend (baseline 0.15 -> ADR-0013 0.35 -> ADR-0014 0.45 -> ADR-0015 0.65 out of 4.0, still well short of the 3.0/4.0 promotion bar) alongside a new, arguably sharper critical safety error on held-out item `mtr-v2-heldout-0013` (endorsing invented numeric recipes) in the exact family corpus v3 added 8 dedicated training items to fix. `docs/decisions/ADR-0015-outcome.md` (revised) synthesizes the full four-cycle arc (ADR-0011/0013/0014/0015) and records both signals as a genuinely mixed real result rather than a uniform negative or positive one: the governed execution/review pipeline itself (real training, real sandboxing, real independent review, honest reporting, zero fabrication, and a transparent same-day self-correction once a gap was caught) worked correctly throughout; the corpus-growth-vs-method-change decision is left explicitly open for Rook. `examples/metatrainer-corpus-addition-four-cycle-lesson/` adds this corrected, mixed-signal finding as new draft corpus case-study material (not yet independently audited or admitted to any training-eligible corpus), teaching the reasoning pattern that two real, partially-disagreeing signals about the same system should both be reported honestly rather than one being treated as the whole picture, and that a document's own prior conclusion should be transparently revised, not defended, once material new evidence surfaces.
- `held-out-eval` CLI (`packages/held-out-eval/src/held_out_eval/cli.py`, issue #56): minimal, stdlib-only argparse CLI (`held-out-eval` console script; no click/typer) for bash/CI-orchestrated training pipelines with no Python glue, operating on the same on-disk JSON registry via the existing `save()`/`load()` Python API. Subcommands: `register-train`, `register-held-out`, `check` (read-only pre-scoring contamination gate), `show`. Meaningful CI exit codes (0 = clean/success, 1 = contamination or load/argument error, 2 = argparse usage error). `--help` documents every subcommand. README gets a CLI usage example alongside the existing Python API example. 22 new CLI-specific tests (success and failure/contamination path per subcommand, plus `--help`, schema-version-load-failure, and CLI/Python-API on-disk interop coverage) added to the package's existing 24-test suite (46 total, all passing). Backlog item per the issue's own priority note; not a blocker for the PyPI-publish track.
- ADR-0016: rewrites `examples/pilot-metatrainer-v3/`'s `confabulated_recipe_detection` family in place (8 -> 11 records; corpus totals 160 -> 163, train 112 -> 115) after diagnosis found the original 8 records were long, third-person, retrospective meta-commentary about the historical ADR-0014 incident that never rehearsed held-out item `mtr-v2-heldout-0013`'s own short, first-person, closed-question "Can X? -> No, because..." shape — a plausible cause of that item's regression in ADR-0015 (from demonstrating the fabrication to explicitly endorsing it as policy). Keeps 2 of the original 8 as accurate scaffolding/context and adds 9 new short, first-person, closed-question examples directly mirroring the tested shape, varying the invented content (a numeric recipe, a cost figure, a date, a percentage, a citation, a resource-usage figure, a rounded number, a citation locator, a benchmark score). Does not change train/held-out split boundaries; `validate_dataset.py` (16/16 checks) still passes clean.
- ADR-0016's gated execution runner (`examples/pilot-metatrainer-v2/run_bounded_cycle_adr0016.py`, `docs/decisions/ADR-0016-execution-config.md`): a mechanical adaptation of the proven ADR-0015 runner to the PR #93-rewritten corpus v3 content (commit `16b0108291f549d5e5f6b0e1f409a65c3d6fdd92`). Reuses ADR-0015's training configuration basis (`learning_rate=5e-6`, one-epoch-per-corpus-size invariant, evaluator, contamination machinery, the 16384MB memory ceiling) unchanged; only the dataset file hashes (now pointing at the rewritten corpus), `MAX_STEPS` (112->115) and `SAVE_STEPS` (56->58) to track the corpus's new 115-example train split, the run id (`adr0016-metatrainer-sft-20260922`), and the approval namespace (`codevolt-adr0016`) are new, under a fresh trust-root copy (`approval_allowed_signers_adr0016`) requiring its own three-gate signing. Validation-only mode is exercised; no training is performed or authorized by this change.
