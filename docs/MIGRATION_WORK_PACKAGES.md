# Migration work packages

These packages transfer learning from experimental repositories into CodeVolt MDF. They are sequential unless an owner explicitly records safe independence.

## WP-01 — Freeze and inventory

**Question:** What exact evidence and code exist locally versus remotely?

Produce immutable starting-state records for each repository, scheduler and host. Do not change model artifacts or classify quality yet. Complete when every dirty path has an identity and no producer is adding new files.

## WP-02 — Tiny Model P1 admission

**Question:** Is the locally reported Run 3 classifier result reproducible and admissible?

Validate source/dataset separation, configuration, checkpoint identity, held-out metrics, resource evidence, and clean reproduction. Require independent review. Complete with `accepted`, `rejected`, or `invalid`; do not deploy.

## WP-03 — P2 deterministic repair

**Question:** Can the structured-extraction dataset be regenerated byte-identically and admitted?

Correct Python compatibility and timestamp nondeterminism test-first. Regenerate in isolation, compare hashes, and request licence/privacy/contamination review. Stop before training if admission is incomplete.

## WP-04 — Mac Phase 3 reconciliation

**Question:** Which scheduler artifacts change a framework or tool decision?

Apply the playbook dispositions to the backlog. Prefer one aggregate over hundreds of repeated tick files. Preserve negative results. Do not resume the scheduler unless a distinct question, budget and stop condition are approved.

## WP-05 — Capability extraction

**Question:** Which proven experimental capabilities belong in the public framework?

For each candidate, record provenance, privacy boundary, generic value, tests, and an adopt/adapt/defer/reject decision. Migrate contracts and synthetic fixtures, not private data or host-specific claims.

Candidates include evidence bundles, held-out evaluation separation, scheduler budgets, kill switches, cleanup verification, partial-layer training, retrieval admission, and invalid-result handling.

## WP-06 — Mac shadow-serving package

**Question:** Can an admitted candidate run reproducibly on the Mac without operational authority?

Define export, conversion, quantisation, artifact equivalence, resource benchmarks, adversarial tests, monitoring, and rollback. Complete with a reviewed shadow-only package; live platform use remains an owner decision.
